## 1. Что мы строим

Платформа для уроков информатики в школах Узбекистана. Она объединяет:

1. **Уроки со сценарием.** Урок состоит из этапов с таймингом: теория (слайды), практика, тест, живая викторина. Этапы могут переключаться автоматически. Есть готовые программы и конструктор, в котором учитель собирает урок сам.
2. **Практика в настоящих программах, а не в имитациях.** Ученик работает в Word, Excel, PowerPoint, редакторе кода и т. д. Система проверяет сохранённый файл по критериям и делает скриншот экрана перед концом практики.
3. **Закрытая среда на ПК ученика (киоск).** Ученик видит только программы и сайты, разрешённые на текущем этапе урока. У него есть своя папка с работами, и доступ есть только к ней.
4. **Управление классом.** Синхронная презентация или трансляция экрана учителя, блокировка «Внимание» для всех, для выбранных или для одного ученика, миниатюры экранов, команды на весь класс.
5. **Журнал и КТП.** Импорт КТП из Excel и Word, оценки по 5-балльной шкале, автоматическое предложение оценки по результатам и удобный перенос оценок в eMaktab.

Один продукт, два режима:

| Режим | Где работает | Для чего | Цена |
|---|---|---|---|
| Веб | любой браузер | подготовка уроков, журнал, домашние задания, бесплатный тариф | бесплатно для учителя |
| Десктоп | компьютерный класс школы (Windows) | киоск, практика в настоящих программах, управление классом | лицензия на класс |

Что именно доступно в каждом режиме — в таблице §4.11.

## 2. Позиционирование и модель продаж

**Ориентир среди конкурентов — LUWO** (luwo.ai). Это готовый предмет «информатика» для 1–8 классов: презентации, тренажёры-имитации и викторина в конце урока. Работает в браузере, поэтому ученик может уйти с вкладки (платформа это только фиксирует). Вход в LUWO: код урока → выбор имени → персональный код. На старте брали около $20 за ученика в год.

**Наши отличия:**
- закрытая среда на ПК;
- практика в настоящих программах с автопроверкой файла;
- скриншот работы и сдача работы;
- автоматическая подстановка имени ученика за его компьютером;
- гибкие режимы показа и блокировки;
- журнал с импортом КТП;
- учитель строит свои уроки;
- цена за класс, а не за ученика.

**Роли:** суперадмин (мы), администратор школы (директор или завуч), учитель, ученик.

**Тарифы:**
- **Учитель — бесплатно.** Регистрация, методические материалы и обучение, конструктор уроков, библиотека, журнал и КТП, один личный класс в веб-режиме.
- **Школа — лицензия на класс в год.** Одна цена за любой класс, без пересчёта на учеников. Класс — это реальный класс школы («8А»). Техническое ограничение — до 40 учеников. Оно защищает от склеивания классов и на цену не влияет.
- **Обычный вход в школу:** пилот на одну параллель на учебный год, затем вся школа со скидкой за полное подключение.
- Цены в сумах определим позже.

Платными делаем функции, которые ценит администрация школы: киоск, практику с проверкой, управление классом, все классы школы и отчёты.

## 3. Жёсткие ограничения

### 3.1 Слабые компьютеры — главное ограничение

Целевое «худшее» железо (предварительно, уточняется в шаге 0.1 плана):
Windows 10/11 x64 Pro · 4 ГБ ОЗУ · старый двухъядерный процессор · HDD · экран 1366×768 · сеть в кабинете 100 Мбит/с · нестабильный интернет.

**Бюджеты производительности.** Цели предварительные, уточнить по замерам из шага 0.3.

| Метрика | Цель |
|---|---|
| ОЗУ клиента ученика в простое (host + WebView2) | ≤ 300 МБ |
| Загрузка процессора клиентом ученика в простое | < 2 % |
| Холодный старт до экрана входа (HDD) | ≤ 10 с |
| Начальный JS веб-клиента | ≤ 200 КБ gzip |
| Слайд | WebP, ≤ 1600 px по ширине, ≤ 150 КБ |
| Миниатюра экрана ученика | ≤ 320 px, ≤ 30 КБ, не чаще 1 кадра в 3 с |
| Трансляция экрана учителя | ≤ 1280×720, ≤ 5 кадров/с, только изменившиеся области |
| Скриншот для проверки работы | ≤ 1920 px, JPEG, ≤ 400 КБ |
| Папка ученика | квота 200 МБ, файл ≤ 50 МБ (настраивается школой) |
| Автопроверка файла практики | ≤ 1 с на файл, без интернета |

**Правила оптимизации:**
- **Презентация на уроке передаётся как номер слайда, а не как видео.** Учитель листает, ученикам уходит «слайд 7», и клиент рисует этот слайд из своего кэша. Видеотрансляция экрана нужна только тогда, когда учитель показывает живую программу.
- Миниатюры экранов снимаются, только пока у учителя открыта панель класса, и отправляются, только если картинка изменилась.
- Видео, трансляции и скриншоты идут по локальной сети кабинета. В облако скриншоты уходят в фоне, после урока.
- Фронтенд пишем на Svelte, без тяжёлых UI-библиотек и без декоративных анимаций. Длинные списки виртуализируем, изображения грузим лениво (lazy load). Шрифт системный, веб-шрифты не загружаем.
- Одновременно открыта максимум одна внешняя платформа (сайт). Остальные вкладки выгружаются.
- Когда урока нет, клиент ученика ничего не делает в фоне.
- Новую зависимость добавляем только после проверки её веса и необходимости.

### 3.2 Windows

- Поддерживаем Windows 10 и 11 (x64). Windows 7 и 8 не поддерживаем: их не поддерживают ни WebView2, ни Electron 23+, ни Tauri 2.12+.
- В школах обычно стоит редакция **Pro**. Встроенный Shell Launcher есть только в Enterprise и Education, поэтому блокировку делаем своими средствами (§8).
- WebView2 Runtime предустановлен в Windows 11 и уже стоит на подавляющем большинстве Windows 10. Установщик всё равно должен поставить его, если не найдёт. Офлайн-установщик WebView2 кладём в комплект, потому что интернет в школах ненадёжный.

### 3.3 Сеть

- **Через облако:** вход, уроки, журнал, результаты, лицензии, синхронизация папок учеников и резервный канал команд.
- **Через локальную сеть кабинета** (Class Hub на ПК учителя): миниатюры, трансляция, блокировка, живая викторина, скриншоты и команды на уроке.
- Если интернет пропал посреди урока, урок продолжается. События, результаты, скриншоты и файлы копятся и уходят на сервер, когда связь вернётся.

### 3.4 Данные детей и закон

- Об ученике храним минимум: имя, фамилию, класс, логин и хэш персонального кода. Никаких телефонов, дат рождения, фото лица и адресов.
- Скриншоты экранов и файлы работ — это учебные материалы. Храним их до конца учебного года (срок настраивает школа), потом удаляем автоматически.
- Биометрию (лица, отпечатки) не собираем вообще.
- Закон РУз «О персональных данных», ст. 27¹ в редакции от 26.03.2026:
  - в Узбекистане обязательно хранить биометрические и генетические данные и данные абонентов телеком-операторов;
  - остальные данные можно хранить за рубежом при одном из условий: страна входит в перечень Кабмина, применяются стандартные договорные условия или соблюдаются международные стандарты из утверждённого перечня.
- **Решение по умолчанию: основной сервер — в Узбекистане.** Перед запуском обязательно проконсультироваться с юристом.

## 4. Функции урока (подробно)

### 4.1 Вход ученика

**В компьютерном классе (десктоп).** Код урока не нужен: ПК зарегистрирован в кабинете, и система знает, какой урок в нём запущен.

1. Учитель на своём ПК запускает урок для класса (например, «8А»).
2. На ПК учеников экран входа сам переключается на этот урок.
3. **Автоподстановка имени по рассадке.** Система помнит, кто из этого класса сидел за этим ПК в прошлый раз, и сразу показывает «Алиев Тимур» с полем для персонального кода.
4. Кнопка **«Это не я»** открывает список класса крупными кнопками. Ученик выбирает себя и вводит код.
5. После успешного входа рассадка обновляется сама. На первом уроке ученики выбирают себя вручную, а дальше имена подставляются автоматически.
6. Учитель видит рассадку в панели и может поправить её перетаскиванием.
7. Если один и тот же ученик пытается войти со второго ПК, первый сеанс закрывается, а учитель получает уведомление.
8. Кто не вошёл, автоматически отмечается как отсутствующий (учитель может исправить).

**В браузере (веб, дома или без киоска).** Как в LUWO: код урока → выбор себя из списка класса → персональный код.

**Персональный код:** 4–6 цифр. После N неверных попыток вход ученика блокируется на время. Учитель может показать или сбросить код, а карточки с QR и кодом печатаются из системы.

### 4.2 Рабочий стол ученика

После входа ученик видит только плитки программ и сайтов, **разрешённых на текущем этапе урока**, и свою папку «Мои работы». При смене этапа набор плиток меняется сам. Учитель может добавить или убрать плитку на ходу, для всех или для выбранных учеников.

### 4.3 Сценарий урока

Урок — это последовательность этапов. Пример по умолчанию (45 минут):

| Этап | Тип | Длительность |
|---|---|---|
| Теория | slides | 10 мин |
| Практика | practice | 25 мин |
| Викторина | live_quiz | 7 мин |
| Итоги | summary | 3 мин |

У каждого этапа есть:
- тип;
- длительность;
- разрешённые программы и сайты;
- правило автоперехода (вручную, по таймеру, после обратного отсчёта 10 с);
- правило скриншота (§4.8).

Управление у учителя: «Старт», «Пауза таймера», «+5 минут», «Пропустить», «Назад». Тесты и викторины запускаются автоматически, когда начинается их этап, после обратного отсчёта на экранах.

### 4.4 Режимы показа

Учитель выбирает режим в любой момент урока:

| Режим | Что видят ученики | Нагрузка |
|---|---|---|
| **Презентация** | текущий слайд учителя (синхронно, рисуется локально), у учителя панель управления | минимальная |
| **Мой экран: весь экран** | живой экран учителя, ввод учеников заблокирован | средняя (LAN) |
| **Мой экран: в окне** | экран учителя в окне, ученик может параллельно повторять в своей программе | средняя (LAN) |
| **Экран ученика** | экран выбранного ученика у всех (показать хорошую работу) | средняя (LAN) |
| **Свободно** | каждый работает сам на своём этапе | минимальная |

**Режим докладчика.** Если к ПК учителя подключён проектор вторым экраном, презентация идёт на проектор, а панель управления остаётся на мониторе учителя. Если экран один (дублируется на проектор), есть кнопка «Показ на весь экран» с маленькой плавающей панелью.

### 4.5 Блокировка

- **«Внимание!» для всех:** экраны закрываются надписью «Смотрите на учителя» и, если нужно, текстом учителя. Клавиатура и мышь заблокированы.
- **Выборочно:** блокировка одного ученика из его плитки или нескольких выделенных.
- Разблокировка выполняется так же: всем, выбранным или одному.
- Блокировка держится, даже если оболочка ученика перезапустилась (её держит агент).
- **В браузере** настоящей блокировки нет: только экран поверх страницы. Об этом честно сказано в интерфейсе учителя.

### 4.6 Тесты и викторины

- **Тест** (этап `quiz`): ученик проходит его сам в своём темпе. Вопросы с одним ответом, с несколькими ответами и с вводом ответа. Автопроверка, результат уходит в журнал.
- **Живая викторина** (этап `live_quiz`, в стиле Kahoot):
  - вопрос и таймер показываются на проекторе (экран учителя) и на всех экранах учеников;
  - ученики отвечают цветными кнопками;
  - очки начисляются за правильность и скорость;
  - после каждого вопроса — рейтинг на проекторе, в конце — пьедестал;
  - в классе викторина идёт через Class Hub (минимальная задержка), в вебе — через сервер.

### 4.7 Практика в настоящих программах

Главная идея: **проверяем не программу, а файл, который ученик сохранил.**

Этап `practice` содержит:
- программу из белого списка школы (Word, Excel, PowerPoint, Блокнот, редактор кода и т. д.);
- шаблон: файл задания, который при старте этапа копируется в папку ученика и открывается в программе;
- критерии:
  - **автоматические**, по файлу. Примеры: «есть заголовок 1-го уровня», «шрифт 14 пт», «в ячейке C5 формула СУММ», «не меньше 3 слайдов», «есть картинка», «в HTML есть тег `<table>`»;
  - **ручные**, которые учитель отмечает при просмотре;
- баллы за каждый критерий и пороги для оценки (например, 90 % → «5»).

**Как работает проверка:**
- Оболочка следит за сохранениями в папке ученика. После каждого сохранения файл проверяется по критериям: локально, без интернета, за 1 секунду.
- Учитель в реальном времени видит в панели: «Алиев: 3/5 критериев».
- Ученик видит свой чек-лист, если учитель это включил.

**Проверщики по типам файлов** (пакет `packages/checkers`, TypeScript — ADR-003):

| Тип | Что проверяем | Когда |
|---|---|---|
| `.docx` | стили, заголовки, шрифты, таблицы, картинки, списки | MVP |
| `.xlsx` | значения, формулы, форматы ячеек, диаграммы | MVP |
| `.pptx` | число слайдов, макеты, картинки, текст | MVP |
| `.html` / `.css` | теги, атрибуты, правила CSS | MVP |
| `.txt` | наличие текста или шаблона | MVP |
| `.py` | запуск с тестами в изоляции с таймаутом | позже |
| `.sb3` (Scratch) | использованные блоки, спрайты, события | позже |
| `.ino` (Arduino) | структура кода, при наличии компилятора — сборка | позже |
| Paint, SketchUp, Tinkercad и т. п. | автоматически проверить сложно → скриншот и ручные критерии | — |

### 4.8 Скриншот и сдача работы

- **Автоматический скриншот** за N минут до конца этапа практики (по умолчанию за 5 минут) или до конца урока, если у практики нет таймера. Ещё один снимок делается в момент, когда учитель завершает практику.
- Вместе со скриншотом фиксируется **копия файлов** из папки ученика. Это «сданная работа»: если ученик потом что-то изменит, оценивается версия на момент сдачи.
- Скриншоты сначала идут на ПК учителя по локальной сети, а в облако уходят в фоне.
- **Экран проверки у учителя:** галерея класса. По каждому ученику видны скриншот, сданные файлы, результат автопроверки и ручные критерии. Предложенная оценка подтверждается одним кликом.
- Учитель может сделать скриншот вручную в любой момент: одного ученика или всех.
- В браузере скриншот экрана недоступен. Сдача работы — загрузкой файла.

### 4.9 Папка ученика «Мои работы»

- У каждого ученика своя папка. Он видит **только её**: ни чужих папок, ни дисков компьютера.
- Как устроено (ADR-002):
  - все ученики работают под одной учёткой Windows «Ученик», поэтому права NTFS не могут разделить их между собой;
  - поэтому работы хранятся в хранилище агента, к которому у учётки «Ученик» нет доступа;
  - при входе агент выкладывает в рабочую папку сеанса только файлы этого ученика;
  - при сохранении и при выходе синхронизирует их обратно, а при выходе очищает рабочую папку.
- В диалогах «Открыть» и «Сохранить» видна только «Мои работы». Диски скрыты политиками (проверить в спайке 0.2), а другие файловые менеджеры не запускаются (наблюдатель процессов).
- **Синхронизация с облаком** в фоне, только изменённые файлы. Поэтому работа доступна на любом ПК школы и дома через браузер (просмотр, скачивание, загрузка).
- Квота и ограничения настраиваются школой. Запрещены исполняемые файлы: `.exe`, `.bat`, `.cmd`, `.ps1`, `.vbs`, `.msi`, `.lnk` и подобные.
- Учитель может открыть папку любого ученика своего класса и нажать «Собрать работы»: получится ZIP по классу и уроку.

### 4.10 Журнал и КТП

- **Официальный журнал школ — eMaktab** (бывший Kundalik). Там пятибалльная система, а оценки, введённые онлайн, можно изменить только в течение 72 часов с даты урока. Наш журнал не заменяет eMaktab, а **ускоряет перенос**:
  - вид «как в eMaktab»: те же даты, тот же порядок учеников;
  - экспорт в Excel;
  - напоминание перенести оценки, пока не прошли 72 часа.
- Публичного API eMaktab пока не нашли. Прямую интеграцию проверить позже (бэклог).
- **Журнал класса:** даты уроков, посещаемость (автоматически из входа), оценки 2–5, комментарии. Предложенная оценка рассчитывается по баллам теста, практики и викторины, учитель её подтверждает или меняет.
- **Импорт КТП** из Excel и Word (таблица):
  - мастер сопоставления колонок: №, тема, количество часов, неделя или дата, примечание;
  - предпросмотр перед сохранением;
  - темы КТП привязываются к урокам (вручную или с подсказкой по названию);
  - отметка «проведено», прогресс по плану;
  - экспорт КТП обратно в Excel.
- Настройка школы: допустимый процент изменений КТП (например, 30 %). Система показывает, сколько изменено.
- **Импорт оценок** из Excel (например, перенос уже выставленных оценок) с тем же мастером сопоставления колонок.

### 5.2 ADR-001: C# + WebView2, а не Electron

- **Компьютеры слабые.** Electron кладёт свою копию Chromium в каждый установщик и каждое обновление (больше 100 МБ). WebView2 общий для всех приложений, уже стоит в системе, а на подходящих системах его файлы связаны с Edge. Это экономит диск, память и трафик обновлений.
- **Системные функции всё равно требуют нативного кода:** перехват клавиатуры, служба Windows, политики, захват экрана, работа с файлами. В C# это стандартные API, и автор проекта знает C#.
- **По ОЗУ разница с Electron умеренная**, потому что оба работают на Chromium. Главный выигрыш — размер, обновления и нативный доступ к системе. Основную экономию памяти даёт архитектура (§3.1).
- **Минусы:** два языка (TypeScript и C#) и только Windows. Для школьных компьютерных классов это приемлемо.
- **Страховка:** веб-код обращается к десктопу только через адаптер `apps/web/src/lib/platform.ts`.
- **.NET 10** — LTS-версия, поддержка до ноября 2028 года.

### 5.3 ADR-002: папка ученика через хранилище агента, а не отдельные учётки Windows

- **Вариант «у каждого ученика своя учётка Windows» отклонён.** На каждом ПК появились бы сотни профилей, а первый вход в новый профиль на слабом ПК с HDD занимает минуты.
- **Выбрано:** одна учётка «Ученик» плюс хранилище `C:\ProgramData\Sinf\vault\<studentId>`, доступ к которому есть только у SYSTEM (агента). При входе агент выкладывает файлы ученика в рабочую папку сеанса, а при сохранении и выходе забирает их обратно. Источник истины — облако. Локальное хранилище — кэш, поэтому работа работает офлайн.
- Конфликт версий (работал на двух ПК без связи): сохраняем обе версии, вторую с суффиксом «(копия ПК-05)».

### 5.4 ADR-003: проверщики практики на TypeScript

- Проверщики пишем **один раз** в `packages/checkers` и запускаем в трёх местах:
  - в десктопе: внутри WebView2, файл передаётся через мост, работает без интернета;
  - в браузере: при загрузке файла;
  - на сервере: повторная проверка и спорные случаи.
- Файлы `.docx`, `.xlsx`, `.pptx` — это ZIP с XML внутри, поэтому их можно разбирать лёгкими библиотеками без Office.
- Критерии описываются данными (JSON-схема в `packages/shared`), а не кодом. Конструктор урока собирает их из готовых проверок.

### 5.4а ADR-004: этап 1 — демо только в вебе

На этапе 1 (`STAGE1.md`) делаем только веб-часть, базу SQLite через Drizzle вместо PostgreSQL и храним файлы в локальной папке `data/` вместо S3. Всё работает одним процессом Node. Причины:
- демо должно запускаться в облачной среде Claude Code и на ноутбуке учителя без Docker;
- десктоп для Windows в облаке не собрать.

Схему базы пишем переносимой, чтобы потом перейти на PostgreSQL. Подробно — в `docs/decisions/004-stage1-demo.md`. Технический план шагов этапа 1 — `docs/stage1-architecture.md`; формат контента уроков — ADR-005, протокол реального времени и состояние сеанса — ADR-006.

### 5.5 Мост между вебом и десктопом

- Десктоп загружает **встроенную** сборку `apps/web` из локальных файлов (через виртуальный хост, например `https://app.sinf.local`), а не с сайта. Сборка обновляется вместе с приложением.
- Host внедряет объект `window.sinfHost`. В вебе он доступен через `platform.ts`: `isDesktop`, `role`, `launchApp(id, file?)`, `lockInput()`, `listMyFiles()`, `readMyFile(path)`, `onFileSaved(cb)`, `takeScreenshot()` и т. д.
- Веб-код никогда не вызывает API WebView2 напрямую, только через `platform.ts`. В браузере те же функции либо скрыты, либо заменены веб-аналогами.

### 5.6 Протокол LAN (Class Hub)

- Хаб — это WebSocket-сервер внутри десктоп-приложения учителя.
- Ученики узнают адрес хаба из облачного сеанса урока. Запасной вариант — UDP-broadcast в подсети.
- **Все команды хаба подписываются ключом сеанса, который выдаёт облако.** Клиент ученика игнорирует неподписанные команды. Иначе школьник поднимет «свой хаб» и разблокирует класс.
- Сообщения передаются в JSON с полем `v` (версия протокола). Схемы лежат в `packages/shared/protocol`. C#-модели в `apps/desktop` поддерживаем вручную в соответствии с этими схемами.
- Типы сообщений:
  - `stage.set` — смена этапа;
  - `slide.set` — смена слайда;
  - `lock` / `unlock` — блокировка (`targets: all | [studentIds]`, текст);
  - `demo.start` / `demo.stop` — трансляция (`fullscreen | window`);
  - `apps.set` — набор разрешённых программ;
  - `quiz.*` — живая викторина;
  - `screenshot.request` / `screenshot.result` — скриншоты;
  - `check.result` — результат автопроверки;
  - `thumb` — миниатюра экрана;
  - `session.end` — завершение урока.

## 7. Ключевые сценарии

1. **Учитель приходит сам.** Регистрируется, импортирует свой КТП, берёт урок из библиотеки или собирает свой и проводит его в веб-режиме с одним классом.
2. **Школа покупает пилот.** Администратор школы:
   - получает лицензию на параллель;
   - загружает списки учеников (вставкой из Excel);
   - печатает карточки с персональными кодами;
   - задаёт белый список программ.
3. **Урок в кабинете.**
   - ПК учеников стоят в киоске на экране входа.
   - Учитель запускает урок для «8А». На каждом ПК подставляется имя по рассадке, ученик вводит свой код.
   - **Теория:** режим «Презентация», учитель листает слайды у всех. При необходимости — «Внимание!» или «Мой экран».
   - **Практика:** у учеников открываются только Word и папка, шаблон уже лежит в папке. Учитель видит миниатюры и счёт критериев. За 5 минут до конца — автоматический скриншот и фиксация файлов.
   - **Живая викторина:** запускается сама по таймеру, рейтинг выводится на проектор.
   - **Итоги:** учитель нажимает «Завершить урок», у всех происходит выход. Посещаемость и результаты уходят в журнал.
4. **После урока.** Учитель открывает галерею работ, подтверждает предложенные оценки, ставит отметку «проведено» в теме КТП и выгружает оценки для eMaktab.
5. **Дома.** Ученик открывает в браузере свою папку «Мои работы» и продолжает работу.

## 8. Киоск: как удерживаем ученика внутри

- Отдельная локальная учётка Windows «Ученик» без прав администратора, с автовходом.
- Для этой учётки вместо `explorer.exe` запускается наша оболочка. Способ проверяем в спайке 0.2.
- Агент ставит для учётки политики Windows:
  - запрет диспетчера задач, смены пароля, блокировки и выхода через меню Ctrl+Alt+Del;
  - скрытие дисков в диалогах открытия и сохранения.
- Низкоуровневый перехват клавиатуры: Win, Alt+Tab, Alt+Esc, Ctrl+Esc, Alt+F4, Alt+Space.
- Ctrl+Alt+Del перехватить нельзя, поэтому закрываем пункты его меню политиками.
- Наблюдатель процессов закрывает всё, что не входит в белый список текущего этапа (в том числе другие файловые менеджеры).
- В WebView2: белый список доменов, новые окна открываются внутри приложения, загрузки идут только в «Мои работы», DevTools и контекстное меню отключены.
- Поверх запущенных программ висит тонкая панель: «Вернуться к уроку», таймер этапа, «Поднять руку».
- Агент (служба Windows) перезапускает оболочку, если её убили, и держит блокировку, даже если оболочка упала.
- Выход для администратора: секретная комбинация клавиш и пароль. Хэш пароля хранится локально, поэтому выход работает без интернета.

## 9. Правила работы для Claude Code

1. Работаем по активному плану (сейчас `STAGE1.md`, после него — `PLAN.md`) **по одному шагу**. Перед шагом прочитай его целиком. После шага:
   - отметь `[x]`;
   - добавь строку в журнал этого плана;
   - перечисли автору, что ему нужно проверить руками;
   - создай pull request.

   К следующему шагу переходи только после подтверждения автора.
2. Если шаг требует решения, которого нет в этих файлах, спроси автора, а не придумывай. Принятое архитектурное решение записывай в `docs/decisions/NNN-название.md`.
3. Код, имена и комментарии — на английском. Строки интерфейса — только через i18n (uz, ru). Документация — на русском.
4. TypeScript в строгом режиме, без `any`. Входные данные API проверяются zod-схемами из `packages/shared`.
5. Не добавляй зависимость без причины. Для веба следи за бюджетом бандла (проверка в CI).
6. Тесты: Vitest для TypeScript, xUnit для C#. Логика прав, лицензий, протокола LAN и проверщиков практики обязательно покрывается тестами. У каждого проверщика есть набор эталонных файлов «правильно / неправильно».
7. Секреты хранятся только в `.env`. В git кладём `.env.example`.
8. Десктоп и агент собираются и запускаются только на Windows. В Linux-окружении код пишется, а сборка и проверка идут в CI (`windows-latest`) или на машине автора. В этом случае явно перечисли автору, что ему нужно проверить руками.
9. Ничего в киоске не «упрощай» ради удобства разработки. Для этого есть флаг режима разработки (`--dev`), и его нельзя включить без пароля администратора.

## 10. Команды

| `pnpm test` | Vitest во всех пакетах (`pnpm test:watch` — в режиме наблюдения) |


Сервер: `pnpm dev` → http://localhost:3000/health. База — `data/sinf.db`; при пустой базе демо-данные создаются сами. Демо-учитель `demo@sinf.local`, пароль — `DEMO_TEACHER_PASSWORD` из `.env`. Сброс демо — `pnpm seed --reset` или `POST /api/demo/reset` с cookie учителя.

Запуск для урока — `docs/deploy.md`: ноутбук в локальной сети (`pnpm build && pnpm start`, адрес `http://192.168.x.x:3000`) или сервер с доменом (`docker compose -f deploy/docker-compose.yml up -d --build`, Caddy даёт HTTPS).

Проверка перед PR: `pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build`.

Windows-приложение (`apps/desktop`, своё окно на WebView2, шаг 6.1 раньше срока — ADR-008) собирает GitHub Actions на `windows-latest`: workflow **Windows app**, архив в Artifacts. В Linux-окружении оно не собирается (§9.8). Собрать на своей машине:

```powershell
pnpm build
dotnet publish apps/desktop/Sinf.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
./tools/package-windows.ps1
```

Агент (служба Windows) на этапе 1 не собирается (ADR-004); команды для него добавим в фазе 6.

## 11. Глоссарий

- **Киоск / оболочка** — наше приложение на ПК ученика, из которого нельзя выйти.
- **Пульт учителя** — десктоп-приложение в режиме teacher.
- **Class Hub** — WebSocket-сервер в пульте учителя, через который идёт управление классом по локальной сети.
- **Агент** — служба Windows на ПК ученика: политики, watchdog, хранилище работ.
- **Сеанс урока** — урок, запущенный учителем для конкретного класса.
- **Этап** — часть урока со своим типом, таймером и набором разрешённых программ.
- **Рассадка** — запомненная связь «ПК ↔ ученик» для класса. По ней подставляется имя при входе.
- **Критерий** — одно проверяемое требование к работе (автоматическое или ручное).
- **Сданная работа** — скриншот и копия файлов на момент сдачи.
- **Параллель** — все классы одного года обучения (8А, 8Б, 8В).
- **КТП** — календарно-тематический план.
