# ADR-005: формат импортированного контента уроков

- **Статус:** принято
- **Дата:** 2026-11-12
- **Связано:** `STAGE1.md` S1.2, ADR-004; схемы в `packages/shared/src/lesson.ts`

## Контекст

Уроки автора лежат в двух автономных HTML-файлах (`content-src/1-klass-2-chetvert/`). Внутри — данные в JS-переменных (`APPS`, `PICS`, `ABC`, `ABCC`), 78 скриншотов в base64 в скрытом `<svg><defs>` (их получает любой открытый урок), 14 сценариев учителя со своими 161 встроенными JPEG. Платформе нужен формат, который проверяется схемой, грузится по одному уроку и кэшируется.

## Решение

Команда `pnpm import:html <файл детей> <файл учителя> <папка>` разбирает файлы без выполнения их кода (JSON-литералы читаются сканером, HTML — парсером parse5) и пишет в `content/<курс>/`:

| Файл | Что внутри |
|---|---|
| `course.json` | список уроков (для меню), `ABC`/`ABCC`, общие SVG-определения слайдов (`url(#dsk)` и т. п.), ссылки на стили и картинки тренажёра |
| `lessons/<id>.json` | урок по схеме `LessonSchema`: этапы с хронометражем, экраны, ссылка на сценарий, список своих картинок `media` |
| `scenarios/<id>.html` | сценарий учителя — отдельный HTML-документ без скриптов |
| `pics.json` | 115 SVG-картинок тренажёра (`PICS`), общие для всех уроков (85 КБ) |
| `lesson.css` | стили автора для слайдов и тренажёра |
| `media/<хэш>.webp` | картинки |
| `import-report.json` | отчёт импорта |

Имя папки — идентификатор курса. Импорт полностью пересоздаёт перечисленные файлы, результат побайтово повторяется.

### Картинки

- Каждый `<use href="#g03"/>` заменяется на `<image href="/content/<курс>/media/<хэш>.webp">` с теми же размерами. Экран грузит только свои картинки и только когда его показывают.
- JPEG → WebP: ширина до 1190 px, размер до 150 КБ (качество снижается ступенями от 80, пока файл не уложится).
- Имя файла — первые 16 символов SHA-256 содержимого WebP. Одинаковые картинки детского файла и сценариев хранятся один раз, файлы можно кэшировать навсегда.
- Картинки, на которые никто не ссылается, не записываются.
- Ссылки абсолютные, с префиксом `/content` — сервер раздаёт папку `content/` по этому адресу (S1.3).

### Экраны

- Типы экранов: `slide` (классы автора `title`, `text`, `text wide`), `step` (шаг практики Paint: номер «Шаг N» и уровень ★/★★/★★★/«свободное»), `type` («Напечатай слово»), `game` (уровень тренажёра). «Слайды» автора = `slide` + `step`.
- Уровни тренажёра хранятся в формате автора (поля `stars`, `say`, `cards`, `opts`…), схемы строгие: новое поле в исходнике ломает импорт и сразу видно.
- Текст уровней (`say`, `txt`, подписи групп) — обычный текст. Проигрыватель выводит его как текст, а не как HTML.

### Этапы

- Хронометраж берётся из полосы `.timeline` сценария учителя: «0–2 приветствие · 2–5 цель · 5–15 теория · 15–37 практика: 9 + отдых 4 + 9 · 37–42 рефлексия · 42–45 итог». Практика хранит части `work 9 / rest 4 / work 9` — для «Отдыха» в S1.8. Цвет сегмента даёт `place`: проектор или компьютер.
- Ключи этапов фиксированы: `greeting`, `goal`, `theory`, `practice`, `reflection`, `summary`. Подпись автора сохраняется в `title`: в k16 этап рефлексии называется «выставка».
- Этап экрана — из `.s-stage` слайда или поля `stage` уровня. Титульные слайды и «Напечатай слово» этапа не указывают: они получают этап **следующего** экрана. Титульный слайд открывает приветствие, а «Напечатай слово» во всех 14 уроках стоит прямо перед тренажёром практики (за компьютером).

### Очистка HTML

Удаляются `<script>`, фреймы, `<object>`, `<link>`, `<base>`, формы, `meta http-equiv`, атрибуты `on*`, SVG-анимации `href`. Разрешены только ссылки `#id` и `/content/…`; стили с `@import` или внешним `url()` удаляются. Из сценариев убирается встроенная копия презентации для детей (`#deck`) и кнопки, которым нужны скрипты: показ на проекторе делает сама платформа (S1.9).

## Последствия

- Вес курса: 20 МБ исходников → 7 МБ (`content/`, коммитится в git). Картинки урока кружка — 200–400 КБ, госпрограммы — 0–60 КБ.
- `sharp` и `parse5` нужны только для импорта (devDependencies сервера). Для запуска демо импорт не нужен: результат уже в репозитории.
- Если автор поменяет исходники, нужно заново запустить импорт и закоммитить `content/`. Тест `apps/server/test/content.test.ts` проверяет готовый контент по критериям S1.2.
