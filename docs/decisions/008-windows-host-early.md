# ADR-008: Windows-приложение раньше срока, портативным архивом

- **Статус:** принято
- **Дата:** 2026-11-13
- **Связано:** `CLAUDE.md` §5.2 (ADR-001), §5.5, §9.8; `PLAN.md` шаг 6.1; ADR-004

## Контекст

Автору нужно показывать и проверять работу на компьютере, а не только в браузере: «версия, которая будет работать под Windows, пока без блокировки». Этап 1 (`STAGE1.md`) по плану целиком веб, десктоп должен был появиться в фазе 6.

Отдельное требование автора: **приложение не должно открывать внешний браузер**. Если Sinf запускает Chrome или Edge, смысл приложения теряется — интерфейс обязан быть внутри нашего окна.

## Решение

Берём шаг 6.1 (`apps/desktop`, C# .NET 10 + WebView2) раньше очереди, в минимальном виде: **одно окно с панелью учителя внутри**. Киоска, блокировок, трансляции и проверки файлов практики здесь пока нет — это фаза 6 целиком.

1. **Своё окно, не браузер.** WinForms + WebView2 (ADR-001). Внутри окна — тот же веб-клиент, что и в браузере, из папки `web/` пакета. Внешних окон нет: `NewWindowRequested` открывает ссылку в том же окне, `NavigationStarting` отменяет любой переход за пределы нашего сервера.
2. **Сервер внутри пакета.** Приложение запускает `server/node.exe server/dist/index.js` скрыто, ждёт `/health` и только потом показывает интерфейс. Node идёт в комплекте: на школьном ПК его нет и ставить его учителю нельзя. Версию Node в пакет кладём ту же, на которой CI только что проверил сборку: готовый бинарник `better-sqlite3` падает со старым Node 22.12 (0xC0000005) и работает с 22.23.
3. **Портативный архив, а не установщик.** В школе у учителя обычно нет прав администратора. Папку можно положить куда угодно, в том числе на флешку. Поэтому `dotnet publish --self-contained` (на ПК не нужен .NET) и никакой записи в реестр.
4. **Данные — в `%LOCALAPPDATA%\Sinf`,** а не рядом с программой: папка программы может быть только для чтения. Там база, журнал работы и профиль WebView2.
5. **Секреты генерируются при первом запуске** в `%LOCALAPPDATA%\Sinf\config.json`: ключ подписи cookie и пароль учителя (`demo@sinf.local`). Пароль показан в синей полосе окна, иначе войти было бы нечем. В репозиторий не попадает ничего.
6. **Адрес для учеников** приложение определяет само по сетевым адаптерам и показывает в полосе сверху; веб-клиент получает его через мост `window.sinfHost` (`CLAUDE.md` §5.5) и подставляет в подсказку на главной учителя.
7. **Node гасится вместе с окном** — и обычным закрытием, и Windows Job Object с `KILL_ON_JOB_CLOSE`, если приложение снимут через диспетчер задач.
8. **Сборку делает GitHub Actions на `windows-latest`** (`.github/workflows/windows-app.yml`). В Linux-контейнере Windows-сборку не собрать и не проверить (`CLAUDE.md` §9.8), а нативный `better-sqlite3` под Windows нужно собрать именно там. В CI же идёт дымовой тест: упакованный сервер поднимается и отвечает на `/health` и `/api/courses`.

## Последствия

- Автор скачивает архив из вкладки Actions и запускает `Sinf.exe` — окно Sinf, без браузерной обвязки.
- Пакет большой (Node ≈ 80 МБ, .NET self-contained ≈ 70 МБ, зависимости сервера ≈ 80 МБ). Для школы с плохим интернетом это разовая загрузка; уменьшать будем в фазе 6, когда появится установщик (`tools/installer`, Inno Setup) с обновлением только изменившихся файлов.
- Окно и работа на реальном ПК проверяются только автором: в облаке Windows недоступен.
- Киоска по-прежнему нет, и приложение не мешает ученику выйти в другие программы. Пока это инструмент учителя и демонстрации, а не рабочее место ученика.

## Что отклонили

- **Electron** — см. ADR-001.
- **Ярлык, открывающий браузер** — прямо противоречит требованию автора.
- **Установщик сразу** — требует прав администратора, которых у учителя нет; и усложняет проверку, ради которой всё и делается.
- **Отдельные учётные данные для учителя в файле рядом с программой** — папка программы может быть только для чтения и может лежать на флешке, которую носят между компьютерами.
