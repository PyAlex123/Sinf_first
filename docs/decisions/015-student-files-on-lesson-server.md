# ADR-015. «Мои работы» на сервере урока, а не на ПК ученика

- **Статус:** принято без автора (этап 3, шаг H12, 2026-11-21). Решение автора — только вход из дома:
  «код класса с карточки → имя → личный код», только для классов с цифровыми кодами.
- **Связано:** `CLAUDE.md` §4.9, ADR-002 (хранилище агента), ADR-011 (обмен школа ↔ облако), ADR-014
  (у ученика нет своего сервера).

## Контекст

ADR-002 задумывал папку ученика как хранилище **агента** на каждом ПК ученика (`C:\ProgramData\Sinf\vault`),
синхронизируемое с облаком. Агента нет и в первом MVP не будет (ADR-014 §4). Зато на этапе 3 сложилась
другая схема: у ПК ученика нет своего сервера, он открывает урок с ПК учителя (ADR-014 §2). Папка
нужна уже сейчас: для сдачи работ (7.8), практики в Word (6.9) и для работы дома.

## Решение

### 1. Где лежат файлы

- **Главная копия — на платформе.** Там же ученик открывает папку из дома.
- **Рабочая копия — на сервере урока**, то есть на ПК учителя. Она живёт в его базе и в
  `DATA_DIR/files`. На уроке ученик сохраняет работы туда по сети кабинета, без интернета.
- **На ПК ученика постоянно ничего не хранится.** Рабочая папка сеанса появится в H15; при выходе она
  очищается. Работу ребёнка нельзя достать из чужого ПК, потому что её там просто нет.

Хранилище агента из ADR-002 остаётся планом на 6.4–6.8. Если оно появится, то станет кэшем этой же
схемы, источник истины не изменится.

### 2. Как хранится

- Байты файла лежат один раз на содержимое, под его SHA-256: `DATA_DIR/files/<ab>/<sha>`. Строка
  `student_files` даёт им имя в папке ученика.
- Имя никогда не становится путём на диске, поэтому никакое имя не выведет за пределы папки.
- Если содержимое больше никто не называет, его байты удаляются.
- Загрузка идёт потоком во временный файл с подсчётом длины и хэша; в памяти файл не держится.
  Обязателен `Content-Length`, одновременно пишется не больше трёх загрузок, остальные ждут.
- Квота — 200 МБ на ученика, файл — до 50 МБ (`CLAUDE.md` §3.1). Пока это константы
  `packages/shared/src/files.ts`, настройкой школы они станут в 8.1.

### 3. Что можно хранить

- **Белый список расширений** вместо чёрного: документы, таблицы, презентации, картинки, текст,
  html/css, py, sb3, ino. Чёрный список пропустил бы `.js`, `.hta`, `.scr`, `.docm` и всё, что Windows
  запускает двойным щелчком.
- **Имя приводится к виду, который примет Windows:**
  - Юникод NFC;
  - без управляющих и запретных знаков;
  - без точки и пробела в конце;
  - без имён устройств (CON, NUL, COM1…);
  - до 120 знаков.
- Регистр букв не различается, как в Windows: «Рисунок.PNG» и «рисунок.png» — один файл.

### 4. Две версии одного файла

Решаем по содержимому, а не по часам: каждая загрузка несёт хэш версии, из которой сделана (`base`).

- То же содержимое уже есть — ничего не меняется (повтор отправки ничего не плодит).
- `base` совпадает с тем, что лежит сейчас, или имя свободно — файл занимает имя.
- Иначе файл успели изменить в другом месте. Сохраняются обе версии, новая — как «Имя (копия ПК-05).ext»
  (ADR-002, §5.3).

### 5. Школьный ПК и облако

Схема та же, что у результатов уроков (ADR-011), — без часов и без доверия.

- **Вверх.** У строки на ПК учителя есть `cloudSha` (что подтвердила платформа) и `dirty` (есть что
  отправить). Каждый тик уходят до 20 изменений. Если платформа сохранила нашу версию как копию,
  ПК переименовывает свою строку так же. Удалённый файл остаётся строкой без содержимого, пока
  платформа о нём не узнает.
- **Вниз.** Когда ученик входит в урок, ПК учителя спрашивает у платформы его папку (если есть связь)
  и подтягивает новые версии. Неотправленные локальные изменения при этом не трогаются.
- **Без связи** урок работает с тем, что есть на ПК учителя. Учитель видит «ждут связи» в панели
  «Результаты уроков».

### 6. Кто открывает папку

- **Ученик на уроке** — токен урока в заголовках `x-session-id` и `x-participant-token`; в адрес токен
  не кладётся.
- **Ученик дома** — код класса (6 цифр, на карточке) → имя → личный код → подписанная кука на 3 часа.
  - Только для классов с цифровыми кодами: две картинки из шести слишком легко подобрать (решение
    автора).
  - Код класса делает платформа, школьный ПК получает его с росписью.
  - Защита от перебора: 10 неверных кодов класса с одного адреса — 10 минут ожидания; 5 неверных
    личных кодов — 2 минуты.
- **Учитель класса** — смотрит и скачивает, ничего не меняет. «Собрать работы» отдаёт ZIP класса,
  по папке на ученика; архив собирается потоком, без сжатия.
- **Никто другой.** Чужой файл отвечает 404.

### 7. Файлы не исполняются у нас

- Всё отдаётся как вложение (`attachment`) с `X-Content-Type-Options: nosniff` и
  `Content-Security-Policy: sandbox`: html или svg ученика не должен выполниться под входом учителя.
- Показать на странице можно только картинки png, jpeg, gif и webp.

### 8. В киоске

На ПК класса кнопки «Мои работы» на странице урока нет: окно выбора файла показало бы диски
компьютера. Там работа идёт через рабочую папку сеанса (H15).

## Что отклонили

- **Хранить работы на ПК ученика без агента.** Нечем закрыть их от соседа по классу: все ученики
  работают под одной учёткой Windows (ADR-002).
- **Загрузка multipart** (`@fastify/multipart`). Лишняя зависимость. Один файл на запрос
  `application/octet-stream` проще и сразу идёт потоком.
- **Разрешать конфликт по времени изменения.** Часы школьных ПК врут; по содержимому решение не
  зависит от часов.

## Дополнение (этап 3, H16)

- **Шаблон практики.** При входе в урок с заданием шаблон кладётся в папку ребёнка (источник
  «задание»), если файла с таким именем ещё нет.
- **Сданная версия практики** не удаляется из хранилища, пока на неё ссылается строка
  `practice_checks`, даже если ребёнок перезаписал файл.
- **Токен урока после конца урока** ещё 2 минуты открывает папку ребёнка, и только её. Это нужно,
  чтобы последнее сохранение рабочей папки ПК класса не потерялось.
