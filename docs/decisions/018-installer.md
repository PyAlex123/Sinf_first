# ADR-018. Установщик Sinf для компьютерного класса

- **Статус:** принято без автора (этап 3, шаг H17, 2026-11-21). Проверить на железе: установка с
  флешки, установка без WebView2.
- **Связано:** `CLAUDE.md` §3.2 (WebView2 в комплекте), `PLAN.md` 6.10, ADR-008 (портативный архив),
  ADR-014 (один `Sinf.exe` и для учителя, и для учеников).

## Зачем

Портативный архив (ADR-008) надо распаковать и запустить на каждом ПК, а потом на каждом ответить на
вопросы:

- «Что это за компьютер?»;
- имя ПК;
- два вопроса Windows про сеть.

На 15 ПК это долго, и легко ошибиться. Шаг 6.10 требует, чтобы продукт ставился «на 15 ПК с флешки
или по сети без единого вопроса».

## Решение

**Inno Setup 6, только x64** (`tools/installer/sinf.iss`). Он ставит тот же комплект, что архив
(`tools/package-windows.ps1` → `out\Sinf`), в `Program Files\Sinf`. Нужны права администратора: на
школьном ПК их и так даёт тот, кто ставит.

### Роль и имя ПК

- **Тихая установка:**

  ```
  Sinf-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /ROLE=student /PC=ПК-05
  Sinf-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /ROLE=teacher
  ```

- **Обычная установка** спрашивает то же на своей странице: роль, а у ученика — имя ПК, не больше
  20 знаков.
- **Куда попадает ответ.** Установщик пишет его в `{app}\setup.json`. `Sinf.exe` читает этот файл
  при первом запуске каждого пользователя Windows, у которого ещё нет роли, и не показывает окно
  роли. Пользователь важен: киоск работает под учёткой «Ученик», а ставит программу администратор.
- **Разбор** — `SetupFile.Parse` в `desktop-core`, с тестами. Всё сомнительное даёт «ничего», и
  Sinf спрашивает, как раньше:
  - неизвестная роль;
  - ученик без имени или с длинным именем;
  - испорченный файл.

  Ошибка в параметре не должна превращать ПК учителя в киоск, а киоск — в ПК учителя.
- **Тихая установка без `/ROLE`** не пишет `setup.json`: Sinf спросит при первом запуске.
- **Сменить роль** уже настроенного ПК — по-прежнему `Sinf.exe --setup`, на ПК ученика с паролем.
  Повторная установка роль не меняет: у пользователя она уже записана в `config.json`.

### Запуск с Windows

- **ПК ученика.** Запись `Sinf` в `HKLM\…\Run` запускает программу для всех пользователей. Свою
  запись в `HKCU` (H7) Sinf при этом убирает.
- **ПК учителя** с Windows не запускается. Если раньше этот ПК был ученическим, установщик удаляет
  запись из `HKLM`.
- **Один Sinf на сеанс Windows.** Именованный мьютекс не даёт запустить второй экземпляр: двойной
  щелчок или старая запись в `HKCU` дали бы два киоска, которые дерутся за экран, хуки клавиатуры
  и порт сервера. Перезапуск, который Sinf делает сам после смены роли (`--restart`), ждёт, пока
  закроется прежний экземпляр.

### WebView2

- В установщик вложен офлайн-установщик Microsoft (около 170 МБ). Он запускается молча (`/silent
  /install`), только если среды нет: проверяется ключ EdgeUpdate для всего компьютера и для
  пользователя.
- CI скачивает его при каждой сборке и проверяет:
  - размер: это не маленький онлайн-загрузчик;
  - подпись Microsoft.

  В git он не хранится. Без него установщик собирается, но предупреждает об этом при сборке.

### Брандмауэр

- Правило «Sinf» пускает входящие для `Sinf.exe` на всех ПК: поиск учителя по UDP 41234, показ
  экрана.
- Правило «Sinf server» пускает `server\node.exe`, только на ПК учителя: сервер урока на порту 3000.
- Оба правила `profile=any`: школьная сеть у Windows часто «общественная».
- При каждой установке правила создаются заново. Удаление их убирает.

### Обновление и удаление

- Перед заменой файлов работающий Sinf закрывается (`taskkill`). Его сервер урока живёт в
  job-объекте Sinf и закрывается вместе с ним.
- **Удаление убирает:** программу, `setup.json`, запуск с Windows, правила брандмауэра.
- **Удаление оставляет** `%LOCALAPPDATA%\Sinf` каждого пользователя: базу, уроки, работы детей.
  Это данные школы, а не программы. Если их нужно убрать, это отдельное решение школы.

### Проверка в CI

Workflow **Windows app** на `windows-latest` собирает установщик и прогоняет
`tools/installer/smoke.ps1`:

1. Тихая установка ученика. Проверяется:
   - файлы на месте;
   - `setup.json` с ролью и именем;
   - запуск с Windows;
   - правило для `Sinf.exe`, но не для сервера.
2. Переустановка на тот же ПК в роли учителя. Проверяется:
   - запуска с Windows больше нет;
   - оба правила есть.
3. Удаление: ничего из перечисленного не осталось.

Установщик и журналы установки лежат в Artifacts.

## Что не сделано и почему

- **Школа и кабинет в параметрах** (`PLAN.md` 6.10). Пару с платформой задаёт одноразовый код
  (ADR-011): класть токен устройства в командную строку небезопасно. Кабинет компьютер получает при
  подключении. Остаётся как есть.
- **Учётка «Ученик» с автовходом и политиками** — дело агента (6.4), его пока нет (ADR-014).
  Установщик ставит программу; киоск по-прежнему держит сам `Sinf.exe` (H3).
- **Подпись установщика.** Нужен сертификат подписи кода. Без него SmartScreen предупредит при
  запуске с флешки: «Подробнее» → «Выполнить в любом случае». Решить до продажи школам.
- **Автообновление** — шаг 6.11.
