# ADR-023. Автообновление Windows-приложения

- **Статус:** принято (этап 6, шаг B6; решения автора от 2026-11-21: «автообновление — да»)
- **Связано:** PLAN.md 6.11, ADR-018 (установщик), ADR-011 (ПК школы и облако), ADR-014

## Задача

Новая версия Sinf должна сама дойти до всех ПК класса: без флешки, без вопросов Windows, без
прерванного урока. Компьютеры слабые, интернет в школе ненадёжный, а установщик с WebView2 весит
около 200 МБ.

## Решение

### Подпись

- Каждое обновление подписывается ключом **ECDSA P-256** (SHA-256). Подпись покрывает строку
  `sinf-update:<версия>:<sha256>:<размер>` — нельзя подменить ни файл, ни версию.
- Пару ключей автор делает сам: `node tools/update-key.mjs`.
  - Секретный ключ — только в секрете GitHub **`SINF_UPDATE_KEY`**. Не в git, не в чате, не на
    сервере.
  - Открытый — в переменной GitHub **`SINF_UPDATE_PUBLIC_KEY`**. CI вшивает его в программу
    обновления (`AssemblyMetadata`). По желанию — `UPDATE_PUBLIC_KEY` в `.env` сайта: тогда сайт
    сам отказывается принять неподписанную сборку.
- **Без ключа** сборка идёт как обычно, но её программа обновления ничего не ставит и пишет
  об этом в журнал; CI выводит предупреждение. Подпись проверяет **сам компьютер**, а не сервер:
  ни сайт, ни ПК учителя, ни «свой хаб» школьника не могут заставить ПК поставить чужую сборку.
- Старая подписанная версия не ставится поверх новой: принимается только версия выше установленной.

### Сборка (CI, workflow «Windows app»)

- Версия одна на всё: `0.3.<номер запуска>` — `Sinf.exe`, программа обновления, установщик.
- Кроме полного установщика (`Sinf-setup-…exe`, с WebView2) собирается **установщик-обновление**
  `Sinf-update-…exe` (`/DUpdateBuild`): та же программа без WebView2 — десятки МБ, а не двести.
- `tools/sign-update.mjs` подписывает его и пишет `update.json`
  `{version, file, sha256, size, signature}`; артефакт **`Sinf-update-x64`** появляется, только если
  у CI есть секрет.

### Раздача

- **Сайт.** Суперадмин в `/admin` → «Обновления Windows-приложения» загружает `update.json` и
  установщик. Сервер проверяет размер и SHA-256 (и подпись, если знает ключ), хранит две
  последние версии в `<data>/updates/<версия>/`.
  - `GET /api/updates/latest` → `{update, busy}`; `GET /api/updates/<версия>/installer` — без
    входа: установщик не секрет, доверие даёт подпись.
- **ПК учителя.** Его сервер (школьный ПК, связанный с сайтом) при обмене с сайтом забирает новую
  версию себе (`UpdateMirror`) и раздаёт её ученикам по локальной сети. Из интернета — один раз на
  кабинет.
- **`busy`.** Сервер класса отвечает `busy: true`, пока идёт урок (активный сеанс младше 3 часов);
  сайт — всегда `false`.

### Установка на ПК (`apps/updater`, `Sinf.Updater.exe`)

- Маленькая консольная программа (урезанная .NET, один файл ~12 МБ). Установщик создаёт две задачи
  планировщика от **SYSTEM**: `Sinf\Update` — каждые 30 минут, `Sinf\Update at start` — через
  5 минут после запуска Windows. Удаление программы удаляет задачи.
- **Где спрашивать.** Sinf раз в минуту пишет `%LOCALAPPDATA%\Sinf\activity.json`: роль, «идёт
  урок» (у ученика), адрес сервера урока (у учителя — свой, у ученика — найденный учительский) и
  адрес сайта, если ПК связан. Программа обновления читает эти отметки во всех профилях и
  спрашивает сначала сервер класса, потом сайт.
- **Когда ставить.** Только если: ключ есть, версия выше установленной (из записи установщика),
  подпись верна, на этом ПК нет урока (свежая отметка) и сервер класса не говорит `busy`. Иначе —
  в следующий раз.
- **Как ставить.**
  - Скачивает в `{app}\updates` (Program Files — писать туда может только администратор, ребёнок
    не подложит свой файл), сверяет размер и SHA-256 с подписанным `update.json`.
  - Ещё раз проверяет, что урок не начался за время загрузки.
  - Копирует себя в `{app}\updates\run` (установщик заменит исходный файл) и из копии запускает
    установщик: `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE=1`. Установщик сам закрывает Sinf.
  - Пока идёт установка, лежит отметка `{app}\updates\installing` — агент (B7) в это время не
    поднимает оболочку.
  - После установки Sinf запускается снова на тех рабочих столах, где он был открыт
    (`WTSQueryUserToken` + `CreateProcessAsUser`, от имени того пользователя).
- **Роль сохраняется.** Тихая установка без `/ROLE` берёт роль и имя ПК из прошлой установки
  (`GetPreviousData` Inno Setup).
- Журнал — `{app}\updates\updater.log`; `Sinf.Updater.exe --status` показывает решение без
  установки.

### Проверки

- xUnit (`desktop-core`): подпись, сделанная Node (как в CI), принимается; изменённые версия,
  размер, хэш, чужой ключ — нет; сравнение версий; решение «ставить / ждать / нечего / выключено /
  неверная подпись»; отметка урока; порядок источников.
- Vitest (сервер): загрузка, отказ по хэшу, размеру и подписи, только суперадмин, две версии,
  `busy` во время урока, копия на ПК учителя.
- CI на `windows-latest`: задачи планировщика и `--status` после установки; обновление поверх без
  `/ROLE` оставляет роль; полный путь обновления с одноразовым ключом — «старая» версия, урок
  (ждёт), конец урока (ставит), роль и имя ПК на месте.

## Что не сделано и почему

- **Откат версии** — нет: старая сборка не ставится поверх новой (это и защита). Исправление —
  новая версия.
- **Дельта-обновления** — нет: обновление качается целиком, но один раз на кабинет.
- **Подпись Authenticode** (сертификат издателя для Windows SmartScreen) — нет, нужен платный
  сертификат. Наша подпись — для программы обновления, не для Windows.
