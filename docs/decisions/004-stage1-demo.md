# ADR-004: этап 1 — демонстрационный MVP только в вебе

- **Статус:** принято
- **Дата:** 2026-11-12
- **Связано:** `STAGE1.md` §4, `CLAUDE.md` §5.4а

## Контекст

Первая цель проекта — живая демонстрация идеи директору и учителям на настоящем уроке автора («1 класс, II четверть, урок 10»). Демо должно:

- запускаться в облачной среде Claude Code и на ноутбуке учителя без Docker;
- работать на любых устройствах с браузером (ПК, планшет, телефон);
- работать в локальной сети школы без интернета.

Десктоп-приложение и агент для Windows (C# .NET 10, WebView2) в облачной Linux-среде не собрать и не проверить. Для демо они и не нужны: показываем сценарий урока, а не киоск.

## Решение

На этапе 1 отступаем от `CLAUDE.md` так:

1. **Только веб-часть.** В монорепозитории есть `apps/server`, `apps/web`, `packages/shared` и `packages/checkers`. Пакет `checkers` на этапе 1 почти пустой, он нужен для шага D3. Папки `apps/desktop` и `apps/agent` не создаём.
2. **База — SQLite (better-sqlite3) через Drizzle** вместо PostgreSQL. Схему пишем переносимой: без особенностей SQLite, которых нет в PostgreSQL. Потом переходим на PostgreSQL сменой драйвера и миграций.
3. **Файлы хранятся в локальной папке `data/`** вместо S3. Папка в `.gitignore`.
4. **Импортированный контент уроков** лежит в `content/` и коммитится в репозиторий. Исходники автора — в `content-src/`, импорт их не меняет.
5. **Один процесс Node:** API, WebSocket и раздача собранного веба на одном порту (`PORT`, по умолчанию 3000).
6. **Учитель входит под демо-учёткой из сида**, без регистрации. Пароль — `DEMO_TEACHER_PASSWORD` из `.env`.
7. **Excel-выгрузка генерируется на сервере.**

Всё остальное — по `CLAUDE.md`: TypeScript strict без `any`, Svelte 5, Fastify, zod, i18n uz/ru, бюджеты производительности, тесты на Vitest.

## Последствия

- Демо запускается командами `pnpm install && pnpm build && pnpm start` на любой машине с Node.js 22 LTS.
- «Внимание!» в браузере — только экран поверх страницы, без блокировки ввода. Это честно показано в интерфейсе учителя.
- Функции экрана (`getDisplayMedia`) работают только по HTTPS, поэтому в варианте «ноутбук в локальной сети» их нет.
- После этапа 1 по `PLAN.md` доводим до полной версии: PostgreSQL, S3-совместимое хранилище, регистрация, лицензии, десктоп и агент.

## Технические детали каркаса (шаг S1.1)

- pnpm workspaces (`apps/*`, `packages/*`), Node.js 22 LTS, ESM.
- TypeScript 6.0 (typescript-eslint пока не поддерживает TypeScript 7). Общий `tsconfig.base.json` в режиме strict с `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.
- Пакеты workspace экспортируют исходники через условие `@sinf/source` (для typecheck, тестов и `tsx` в dev) и собранный `dist` для продакшна. Поэтому тесты и dev работают без предварительной сборки, а `pnpm build` собирает пакеты по порядку зависимостей.
- Скрипт `import:html` живёт в `apps/server/src/cli/`, рядом с сидом: он использует схемы из `packages/shared` и пишет в `content/`, который потом читает сервер.
