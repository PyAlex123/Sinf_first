# ADR-016. Проверщики файлов практики

- **Статус:** принято без автора (этап 3, шаг H13, 2026-11-21).
- **Связано:** `CLAUDE.md` §4.7, ADR-003 (проверщики на TypeScript, один код в трёх местах), `PLAN.md` 3.6–3.7.

## Решение

### 1. Пакет и зависимости

`packages/checkers` экспортирует одну функцию: `checkFile(байты, имя файла, критерии) → отчёт`. Она
работает в браузере, в WebView2 приложения класса и на сервере, без сети и без Office. Зависимостей
две:

- **`fflate`** — распаковка ZIP. Уже есть у сервера. Распаковываются только нужные XML-части: картинки
  и медиа пропускаются, а часть больше 20 МБ не распаковывается вовсе.
- **`htmlparser2`** — один разборщик и для XML Office, и для HTML ученика.
  - `fast-xml-parser` теряет порядок смешанного содержимого.
  - `saxes` потребовал бы второй разборщик для HTML.
  - `parse5` — честный HTML5, но молча «чинит» незакрытые теги. А для школьной проверки «ты забыл
    `</p>`» — это и есть суть: `htmlparser2` сообщает, какой тег пришлось закрыть за ученика.

CSS читается своим маленьким разборщиком: правила, объявления, вложенные `@media`.

В вебе пакет грузится отдельным куском, только на странице задания: 85 КБ, 34,5 КБ в gzip. Начальный
JS сайта не растёт.

### 2. Критерии — данные

- Задание практики — `PracticeTaskSchema` (`packages/shared/src/practice.ts`): программа, имя файла,
  шаблон, критерии, пороги оценок, показывать ли ученику чек-лист.
- Критерий — **автоматический** (готовая проверка с параметрами, например
  `{ type: 'xlsx.formula', cell: 'C5', function: 'SUM' }`) или **ручной** (отмечает учитель).
- Проверок 49: `.docx` — 10, `.xlsx` — 10, `.pptx` — 9, `.html`/`.css` — 11, текст — 9. Проверки
  текста работают и на `.html`/`.css`.

### 3. Три исхода, а не два

- У каждой проверки исход **«да»**, **«нет»** или **«не удалось определить — проверит учитель»**.
- Файл, который не открывается (старый `.doc`, файл с паролем, переименованный текст), даёт «не удалось
  определить» по всем пунктам, а не «нет»: ребёнок не должен получить «2» за то, что Word сохранил в
  старом формате.
- Формула без сохранённого значения (её сохранила программа, которая не считает) — тоже «не удалось
  определить».

### 4. Что пишет настоящий Office, а библиотеки на Python — нет

Это учтено в коде, и на каждый случай есть эталонный файл.

- **Word:**
  - в русском Word id стилей свои («1», «Заголовок1»), а имя стиля остаётся «heading 1»;
  - слово режется на куски проверкой орфографии;
  - удалённый при рецензировании текст — не текст;
  - шрифт задан через тему (`minorHAnsi`);
  - размер берётся из умолчаний документа, а оформление — по цепочке стилей.
- **Excel:**
  - формулы хранятся по-английски, без «=» («СУММ» → `SUM`);
  - формула, протянутая вниз, хранится один раз («общая формула»);
  - рядом с формулой лежит посчитанное значение;
  - вид ячейки задаётся через таблицу стилей `cellXfs`;
  - тег `[$-419]` в формате — язык, а не валюта;
  - порядок листов берётся из книги.
- **PowerPoint:**
  - порядок слайдов берётся из `sldIdLst`, а не из имён файлов;
  - у записи слайда есть и свой `id`, и `r:id` связи;
  - переходы лежат внутри «альтернативного содержимого».
- **Текст:** UTF-8, «ANSI» (windows-1251) старого Блокнота и UTF-16.

### 5. Эталонные файлы

`tools/fixtures/make_checker_fixtures.py` делает их через python-docx, openpyxl и python-pptx, а потом
правит XML так, как это делает настоящий Office. Файлы закоммичены в `packages/checkers/fixtures`, и
Prettier их не трогает.

**Нужно от автора:** по одному настоящему файлу из его Word, Excel и PowerPoint. Они пойдут в набор
эталонов, и проверка станет надёжнее синтетики.

### 6. Где живёт задание

Урока как сущности в базе пока нет (`PLAN.md` 3.1). Поэтому страница «Задание практики» — конструктор
и проверка эталона:

- критерии собираются из каталога проверок;
- эталон проверяется в браузере и ещё раз на сервере (`POST /api/practice/check`), и оба результата
  должны совпасть;
- «Скопировать задание» даёт JSON, который кладётся в файл урока (H16).

Хранение заданий в базе — вместе с 3.1.

## Скорость

Тест «проверка одного файла меньше 250 мс». Это бюджет из `PLAN.md` 3.6 — меньше 1 с при замедлении
×4 — с запасом. На деле `.docx` проверяется за 20–50 мс.

## Дополнение (этап 3, H16): практика на уроке

Решено без автора; проверить на железе.

### Где проверяется файл

**На сервере урока (ПК учителя), а не в WebView2 ученика.** ADR-003 допускает оба места. Выбран
сервер, потому что:

- один путь и для ПК класса, и для урока в браузере: файл в любом случае приходит на сервер урока
  (H12, H15);
- проверку нельзя подделать с ПК ученика: счёт считает компьютер учителя;
- сеть кабинета локальная, проверка `.docx` — 20–50 мс, поэтому счёт на плитке появляется через
  ~2 с после Ctrl+S (1,5 с ждёт рабочая папка, H15).

Проверщики в браузере остаются на странице «Задание практики» (проверка эталона учителем).

### Задание урока

Задание лежит рядом с уроком: `content/<курс>/practice/<урок>.json`, как викторина. Шаблон — файл
того же курса (`templates/…`). При старте сервера проверяется:

- схема задания;
- имя файла подходит программе;
- шаблон есть и лежит внутри курса.

Пока урок не сущность базы (`PLAN.md` 3.1), задания пишутся руками. Первое — урок-образец «Проба
практики → Оформи документ» (Word, 5 автоматических и 2 ручных критерия). Это образец разработчика,
не авторский урок. Шаблон и эталоны делает `tools/fixtures/make_practice_sample.py`.

### Ход практики

1. **Вход в урок.** Шаблон кладётся в «Мои работы» ребёнка под именем из задания, если файла с
   таким именем ещё нет. Если файл уже есть, это работа ребёнка, и она остаётся. Приложение класса
   приносит шаблон в рабочую папку: оно проверяет папку раз в 20 с, а перед открытием программы с
   отсутствующим файлом сверяет её сразу. Плитка программы открывает этот файл.
2. **Сохранение.** Проверяется каждое сохранение файла нужного вида, то есть с расширением
   программы задания. Имя может быть любым: ребёнок мог сделать «Сохранить как». Учитываются только
   сохранения из урока, по токену урока; из дома — нет. Проверки одного ребёнка идут по очереди.
   Результат попадает в состояние урока (`participant.check`): у учителя на плитке «Практика: 3/5»,
   у ребёнка — чек-лист, если `showChecklist`.
3. **Сдача (`CLAUDE.md` §4.8).**
   - Вместе со снимками всего класса «за 5 минут до конца» и «в конце практики» последняя
     проверенная версия становится сданной. Её байты остаются в хранилище, даже если ребёнок потом
     изменит файл (`collect` смотрит и на `practice_checks`).
   - Сохранение в течение 30 с после конца практики тоже идёт в сданное: программа спросила
     «Сохранить?», когда практика её закрыла.
   - Если урок закончили, не выходя из практики, сдаётся версия на конец урока.
4. **Итоги.**
   - По каждому ребёнку: сданный файл (скачать), каждый критерий с тем, что нашёл проверщик, и
     отметки учителя ✓ / ✗.
   - Отметка учителя главнее проверщика. Она нужна для ручных критериев и для автоматических с
     исходом «проверит учитель». Повторное нажатие снимает отметку.
   - Отметки можно ставить и во время урока, и после.
   - Ребёнку, который ничего не сохранил, отметки тоже можно поставить: например, если работа на
     бумаге.

### Хранение и облако

- **Таблица `practice_checks`** (миграция 0011): одна строка на ребёнка и урок. В ней:
  - последняя проверенная версия: имя, sha, отчёт;
  - сданная версия;
  - отметки учителя.
- **В облако** таблица уходит в пакете урока (`checks`, ADR-011). Как и оценки, она заменяется
  целиком. После отметки или поздней сдачи урок снова встаёт в очередь. Сам файл едет с «Моими
  работами» (H12).

### Найдено и исправлено по дороге

- **После конца урока токен сразу переставал работать.** Из-за этого последнее сохранение рабочей
  папки (H15) не доходило до сервера. Теперь токен ещё 2 минуты открывает папку ребёнка, и только
  её.
- **Сброс демо падал**, если у ребёнка 1А был файл в «Моих работах» (внешний ключ). Теперь сброс
  удаляет файлы и проверки демо-класса.

## Дополнение (этап 6, B5): Scratch, Arduino, Python

**Проверщики** — в `packages/checkers`, как остальные; критерии — данные в `packages/shared/src/practice.ts`.

- **`.sb3` (Scratch 3)** — ZIP с `project.json`: спрайты, переменные и списки, блоки по «опкоду».
  - Проверки: спрайтов не меньше N; скрипт запускается флажком; есть цикл (повторить, всегда,
    повторять пока); есть условие (если, если-иначе, ждать до); переменных и списков не меньше N;
    играет звук; блоков не меньше N; есть блок с заданным опкодом (для всего остального).
  - Меню внутри блоков («тени») и брошенная на поле переменная блоками не считаются.
- **`.ino` (Arduino)** — читается как код, **не компилируется**: компилятора может не быть на ПК
  класса, а проверка должна укладываться в секунду (§3.1).
  - Проверки: есть `setup()` и `loop()`; вызывается функция (`pinMode`, `Serial.begin`…), не меньше
    N раз; используется пин N (первый аргумент `pinMode` / `digitalWrite` / `digitalRead` /
    `analogRead` / `analogWrite`, с подстановкой `#define` и `const int`); скобки и кавычки закрыты.
  - `LED_BUILTIN` считается пином 13: так на Uno и Nano из школьных наборов.
  - Определение функции (`void blink()`) — не вызов; слова в комментариях и строках не считаются.
- **`.py` (Python)** — **без запуска.** Запуск с тестами откладываем: нужна песочница с лимитом
  времени и памяти, которой нет ни в браузере, ни в WebView2, а на сервере это отдельная задача
  безопасности. Решение пересмотреть, когда появится агент или серверная песочница.
  - Проверки: объявлена функция (любая или с именем); переменная получает значение; используется
    for / while / if / def / return / import / input / print / список / try; `print` выводит текст;
    «синтаксис»: кавычки и скобки закрыты, после двоеточия есть блок с отступом, отступы совпадают,
    табуляция и пробелы не смешаны, у `if` / `for` / `def` … есть двоеточие.
  - «Синтаксис» — приближение к тому, что откажется запускать Python, а не полный разбор: он ловит
    типичные ошибки ребёнка и показывает строку («строка 2: нет двоеточия»).
- Текстовые проверки (`txt.*`) работают и на `.py` / `.ino`.

**Программы** `scratch`, `arduino`, `python` добавлены в `PRACTICE_APPS`, `LESSON_APPS` и правила
школы (по умолчанию разрешены). На ПК класса (`AppCatalog.cs`) программа ищется:

- Scratch 3 — `Program Files`, `Program Files (x86)`, `%LOCALAPPDATA%\Programs\Scratch 3`;
- Arduino — сначала IDE 2 (`Arduino IDE`), потом 1.8 (`Arduino\arduino.exe`);
- Python — сначала Thonny (среда для обучения), иначе IDLE самого нового Python 3
  (`pythonw.exe -m idlelib`).

Плитка видна, только если программа нашлась. Ставить их нужно **«для всех пользователей»**: учётка
ученика не видит то, что поставлено в профиль администратора.

**Arduino и папка скетча.** Arduino IDE открывает `blink.ino`, только если он лежит в папке `blink`.
Перед запуском IDE файл переносится в `Мои работы\blink\blink.ino`; синхронизация «Моих работ»
читает и пишет скетч там, а для ребёнка и учителя это по-прежнему файл `blink.ino`. Других вложенных
папок в «Моих работах» нет.
