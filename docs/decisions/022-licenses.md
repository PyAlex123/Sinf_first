# ADR-022. Лицензии школ

- **Статус:** принято без автора (этап 6, B2; автор сказал «делай всё, что можешь»). Автор может
  пересмотреть, особенно что считать платным.
- **Дата:** 2026-11-21
- **Связано:** CLAUDE.md §2 (тарифы), §6 (License), PLAN.md 2.6–2.7, ADR-009 §6 (лицензии отложены —
  этот ADR их вводит), ADR-011 (ПК класса и облако).

## Решения

1. **Лицензия школы — N классов на период** (`licenses`: classesLimit, validFrom, validTo, note).
   Выдаёт, продлевает и отзывает суперадмин в `/admin`. Считается та, что началась и не отозвана, с
   самым поздним концом; отозванная остаётся строкой.
2. **Платное (по лицензии):**
   - классы школы: создать класс школы можно только при действующей лицензии и в её пределах
     (`409 license_needed` / `license_limit`);
   - урок на компьютерах класса (сервер в режиме класса или ПК школы с привязкой) — только для
     класса школы с лицензией;
   - отчёты школы.
3. **Бесплатное:** веб-уроки, журнал, КТП, конструктор, библиотека — и **один личный класс** у
   учителя без школы (`free_limit` на второй). Личный класс живёт на сайте: урок на компьютерах
   класса для него — `license_personal`.
4. **14 дней запаса** после конца лицензии — только для уроков на ПК класса: ПК без связи не должен
   встать посреди четверти из-за того, что не успел узнать о продлении. Новые классы и отчёты —
   строго по сроку.
5. **ПК класса знает лицензию из снимка школы** (`SchoolSnapshot.license`), хранит копию в той же
   таблице и проверяет урок без связи.
6. **Уже созданное не трогаем:** если лимит уменьшили, лишние классы остаются, просто новых не
   добавить.
7. **Демо-школа** получает лицензию на 20 классов на два учебных года при засеве и при сбросе
   демо: показ и тесты не упираются в неё.

## Последствия

- Таблица `licenses` (миграция 0020).
- Новая школа без лицензии может принять учителей, но классы школы и уроки в классе появятся
  только после выдачи лицензии — это надо помнить при пилоте и в `docs/pc-test.md`.
