# ADR-006: протокол реального времени и состояние сеанса на этапе 1

- **Статус:** принято
- **Дата:** 2026-11-12
- **Связано:** `docs/stage1-architecture.md` §5–§7, `STAGE1.md` S1.7–S1.9, CLAUDE.md §5.6

## Контекст

На этапе 1 нет Class Hub и локальной сети кабинета: все клиенты (учитель, ученики, проектор) ходят через сервер. Нужен один протокол для синхронной презентации, таймера этапов, «Внимания!», викторины и миниатюр, который переживает обрывы связи и перезапуск сервера, а потом переносится на хаб (PLAN.md 7.1) без переписывания клиентов.

## Решение

1. **Сервер — единственный источник истины.** Состояние сеанса `SessionState` (этап, таймер, режим, текущий экран, блокировки, викторина, присутствие учеников) хранится на сервере. Клиенты не вычисляют переходы сами: они рисуют присланное состояние и отправляют команды.
2. **Снимок плюс дельты.** При подключении клиент получает `state.snapshot` с полным состоянием и серверным временем `serverNow`; дальше — события-дельты (`stage.changed`, `lock.changed`, …). Таймеры рисуются по серверному времени через смещение `offset = serverNow − Date.now()`, поэтому часы устройств не влияют.
3. **Движок — чистый reducer** в `packages/shared/src/session-engine.ts`: `reduce(state, event, now) → { state, effects }` и `nextTimerAt(state)`. Сервер исполняет эффекты (разослать, записать в базу, завести таймер). Один и тот же код потом работает внутри Class Hub.
4. **Формат сообщений** — JSON `{ v: 1, type, ...payload }` с zod-схемами в `packages/shared/src/protocol.ts` (CLAUDE.md §5.6). Имена команд с префиксом роли: `teacher.*`, `student.*`; события сервера — по предмету: `stage.*`, `lock.*`, `quiz.*`, `student.updated`. Неизвестное сообщение игнорируется с записью в лог.
5. **Подписи команд ключом сеанса** (CLAUDE.md §5.6) на этапе 1 не нужны: единственный источник команд — сервер, которому клиент доверяет по HTTPS. Появятся вместе с хабом.
6. **Устойчивость.** Токен ученика живёт в `sessionStorage`; переподключение с ним продолжает сеанс. Второе устройство того же ученика вытесняет первое (`session.kicked`). Состояние активного сеанса сохраняется в `sessions.stateJson` при каждом переходе и не чаще раза в 5 с; после перезапуска сервера сеанс восстанавливается на паузе.
7. **Один WebSocket на клиента**, JSON и бинарные кадры миниатюр в нём же. Heartbeat 15 с, оффлайн — через 30 с без ответа.

## Последствия

- Задержка «учитель нажал → у ученика сменился экран» равна одному проходу через сервер; в школьной сети это укладывается в 1 с (критерий S1.9).
- Все переходы сценария тестируются без сети и базы, на reducer'е.
- При переносе на Class Hub меняется транспорт и добавляется подпись команд; схемы сообщений и движок остаются.
- Отклонено: хранить таймер на клиентах (разойдутся часы), и CRDT/peer-to-peer (избыточно для класса из 20 человек с одним управляющим).
