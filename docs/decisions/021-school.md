# ADR-021. Школа: настройки, хранение, приглашения, сброс пароля

- **Статус:** принято без автора (этап 5; режим «без остановок»), кроме способа сброса пароля —
  его выбрал автор. Автор может пересмотреть.
- **Дата:** 2026-11-21
- **Связано:** CLAUDE.md §3.4, §4.9, §6 (School.settings, ApprovedApp), PLAN.md 2.1, 2.3, 2.4, 8.1;
  ADR-009 (школы и права), ADR-011 (ПК класса и облако), ADR-020 (% изменений КТП).

## Контекст

Школу ведёт администратор (директор или завуч). До этапа 5 он мог только принимать учителей и
заводить компьютеры; правила школы (квоты, срок хранения, программы) были зашиты в код, а
забывший пароль учитель мог только написать нам.

## Решения

### 1. Правила школы — один набор с умолчаниями (A1)

- `schools.settings` (JSON) хранит пять правил: место на ученика (1–200 МБ), самый большой файл
  (1–50 МБ), день «хранить работы до» (`MM-DD`), программы на уроках, % изменений КТП.
  Потолки — платформенные 200 и 50 МБ из `CLAUDE.md` §3.1: школа может их **уменьшить**, но не
  поднять — диск сервера общий.
- Читаем мягко: чего нет или что испорчено — то по умолчанию; файл не больше места. Поэтому
  старые школы (`{}`) ничего не ломают и миграция данных не нужна.
- Личный класс учителя (без школы) живёт по умолчаниям.
- Меняет только администратор школы и только на сайте; ПК класса получает правила со снимком
  школы (ADR-011) и сам их не меняет.

### 2. Квоты — от школы класса, проверяются трижды (A2)

- Предел берётся из правил школы класса ребёнка в трёх местах: до чтения файла (по заявленной
  длине), при приёме байтов и в ответе папки — чтобы страница отказала сразу и назвала число школы.
- Уменьшение квоты не удаляет то, что уже лежит: папка просто считается полной, пока ребёнок не
  освободит место.
- Файл, пришедший обменом между ПК класса и сайтом, принимается по платформенному пределу (50 МБ):
  он уже был принят по правилам на другой стороне.

### 3. Белый список — из известных программ, фиксируется на урок (A3)

- `ApprovedApp` из `CLAUDE.md` §6 (своя программа школы: путь к `.exe`, аргументы, значок) пока не
  делаем: запуск чужого `.exe` из киоска требует наблюдателя процессов и агента (фазы 6–7, этап 3,
  проверка на железе). Сейчас школа выбирает из пяти программ, которые знает приложение
  (`AppCatalog.cs`); C# не меняется.
- Список школы кладётся в состояние урока при старте и не меняется до его конца: правило «что
  разрешено» не должно меняться посреди урока, а ПК класса работает и без связи.
- Проверка в движке урока (`teacher.apps.set`), а не только на странице: команда в обход страницы
  тоже не даст неразрешённую программу.
- Урок, сохранённый до этапа 5, читается как «разрешено всё».

### 4. Срок хранения — «до дня», раз в год, сам (A4)

- Правило школы — день и месяц: «хранить до 31 июля». С началом следующего дня по Ташкенту
  удаляется всё сделанное раньше. Это и есть «до конца учебного года» из `CLAUDE.md` §3.4, только
  день выбирает школа (лето, конец июня, конец года).
- Удаляются учебные материалы: скриншоты, «Мои работы», не менявшиеся с этого дня, и файлы,
  сданные на практике. Оценки, журнал, отчёты проверок и отметки учителя остаются: это не работы,
  а их оценка. «Сдано» теперь значит «есть время сдачи», а не «есть файл».
- «Мои работы» — по дате последнего изменения: файл, который ребёнок правил в новом учебном году,
  живёт до следующего дня очистки.
- Очистка идёт на сайте и на ПК класса по одному правилу. На ПК — только у себя, без пометки
  «удалено» в обмен: копия там может быть старее той, что ребёнок поменял дома, и пометка стёрла
  бы новую. Первая очистка — через минуту после старта сервера, дальше раз в 6 часов.
- **Важно при первом запуске:** на сайте с данными прошлых лет очистка в первую же минуту удалит
  всё сделанное до последнего дня школы — так и задумано, но перед обновлением стоит знать.

### 5. Панель — вкладки одной страницы, кабинет — текст (A5)

- Панель администратора — та же страница школы (`/school/:id`), вкладки вместо новых страниц;
  вкладка в адресе (`#computers`), чтобы ссылка и обновление открывали её же.
- Кабинет компьютера — по-прежнему текст у ПК (`devices.room`), без таблицы `Room` из
  `CLAUDE.md` §6: группировки по одинаковому тексту хватает, а лишняя сущность потребовала бы
  переноса ПК между кабинетами, которого никто не просил.
- «Старая версия» — ниже самой новой среди ПК этой школы: платформа не знает, какая версия
  последняя (автообновления нет, шаг 6.11).
- Учителей класса назначает администратор и только из учителей школы; на ПК класса — нельзя
  (снимок школы с сайта перезаписал бы).

### 6. Приглашение — одна ссылка на неделю для всего чата (A6)

- Ссылка многоразовая: администратор кидает её в чат учителей, по ней входит каждый. Действует
  7 дней, отзывается в любой момент. Именных приглашений по почте не делаем: почты у платформы
  до A7 не было, а чат учителей в школе есть всегда.
- По ссылке учитель сразу становится учителем школы (не администратором), без заявки: ссылку дал
  администратор — это и есть его решение.
- Хранится только SHA-256 секрета (32 случайных байта): утечка базы не даёт рабочих ссылок.
  Поэтому ссылка видна один раз, при создании.
- Возврат после входа — `?next=`, и только путь этого же сайта (`/…`, не `//…`): иначе ссылка
  «войдите» могла бы увести на чужой сайт.
- Ответ «куда ведёт ссылка» сам говорит, вошёл ли посетитель: странице не нужен отдельный запрос,
  который у гостя кончался бы ошибкой 401.

### 7. Сброс пароля — почта и ссылка от администратора (A7, выбор автора)

- Два пути к одной и той же одноразовой ссылке на час: письмо по просьбе самого учителя и ссылка,
  которую администратор школы (или суперадмин) копирует и отправляет учителю сам — в школе почта у
  учителя часто не та или не читается, а Telegram есть всегда.
- Почта — `nodemailer` по `SMTP_URL` (единственная новая зависимость этапа, только сервер). Без
  `SMTP_URL` письмо печатается в лог: так в разработке и на ПК класса. Адрес сайта в письме —
  `PUBLIC_URL`, без него — адрес, на который пришёл запрос (за прокси может быть `http`, поэтому на
  сервере с доменом `PUBLIC_URL` надо задать).
- Ответ на «забыли пароль» всегда один и тот же: по нему нельзя узнать, есть ли такой учитель.
  Не больше трёх писем за 15 минут на адрес — чужими руками нельзя завалить ящик.
- Новый пароль кончает все прежние входы: у пользователя `session_version`, cookie хранит
  `id:версия`. Старые cookie без версии читаются как версия 0, поэтому обновление никого не
  выкидывает. Новая ссылка гасит прежние, использованная не работает.
- Администратор школы даёт ссылку только учителю своей школы и не суперадмину; на ПК класса
  сброса нет — вход там проверяется через сайт (ADR-011).

Пополняется по шагу A8.
