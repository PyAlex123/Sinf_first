# ADR-021. Школа: настройки, хранение, приглашения, сброс пароля

- **Статус:** принято без автора (этап 5; режим «без остановок»), кроме способа сброса пароля —
  его выбрал автор. Автор может пересмотреть.
- **Дата:** 2026-11-21
- **Связано:** CLAUDE.md §3.4, §4.9, §6 (School.settings, ApprovedApp), PLAN.md 2.1, 2.3, 2.4, 8.1;
  ADR-009 (школы и права), ADR-011 (ПК класса и облако), ADR-020 (% изменений КТП).

## Контекст

Школу ведёт администратор (директор или завуч). До этапа 5 он мог только принимать учителей и
заводить компьютеры; правила школы (квоты, срок хранения, программы) были зашиты в код, а
забывший пароль учитель мог только написать нам.

## Решения

### 1. Правила школы — один набор с умолчаниями (A1)

- `schools.settings` (JSON) хранит пять правил: место на ученика (1–200 МБ), самый большой файл
  (1–50 МБ), день «хранить работы до» (`MM-DD`), программы на уроках, % изменений КТП.
  Потолки — платформенные 200 и 50 МБ из `CLAUDE.md` §3.1: школа может их **уменьшить**, но не
  поднять — диск сервера общий.
- Читаем мягко: чего нет или что испорчено — то по умолчанию; файл не больше места. Поэтому
  старые школы (`{}`) ничего не ломают и миграция данных не нужна.
- Личный класс учителя (без школы) живёт по умолчаниям.
- Меняет только администратор школы и только на сайте; ПК класса получает правила со снимком
  школы (ADR-011) и сам их не меняет.

### 2. Квоты — от школы класса, проверяются трижды (A2)

- Предел берётся из правил школы класса ребёнка в трёх местах: до чтения файла (по заявленной
  длине), при приёме байтов и в ответе папки — чтобы страница отказала сразу и назвала число школы.
- Уменьшение квоты не удаляет то, что уже лежит: папка просто считается полной, пока ребёнок не
  освободит место.
- Файл, пришедший обменом между ПК класса и сайтом, принимается по платформенному пределу (50 МБ):
  он уже был принят по правилам на другой стороне.

Пополняется по шагам A3–A8.
