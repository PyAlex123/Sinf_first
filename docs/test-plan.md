# План теста этапов 3–6 (ноутбук и один ПК)

Сделанное в этапах 3–6 ещё не проверено руками. Этот план собирает четыре инструкции в один порядок
прогона на имеющемся железе:

- `docs/hardware-test.md` — этап 3, класс на ПК;
- `docs/web-test.md` — этап 4, веб;
- `docs/school-test.md` — этап 5, школа;
- `docs/pc-test.md` — этап 6, установка, онлайн и офлайн, обновление.

План не повторяет эти инструкции, а говорит, что, когда и в каком порядке делать. «Должно быть» написано
в самих инструкциях. Всё «не так» — в чат VSCode (раздел «Как сообщать»), я веду
`docs/test-results.md`.

**Решения автора (2026-11-22):**

- **Железо:** ноутбук и один ПК.
- **Агент** (`pc-test.md`, раздел 7) — **не в этом прогоне**.
- **PostgreSQL (B9):** вариант 2 из ADR-025 — после теста, отдельным этапом.

## Подготовка (30 минут)

**Код.** Всё лежит в ветке `claude/stage6`, этапы 3–5 туда входят. В VSCode, в корне репозитория:

```bash
git fetch
```
```bash
git checkout claude/stage6
```
```bash
corepack enable
```
```bash
pnpm install
```
```bash
cp .env.example .env
```

**В `.env`:**

- `DEMO_TEACHER_PASSWORD`;
- длинный `SESSION_SECRET`;
- `SUPERADMIN_EMAIL` и `SUPERADMIN_PASSWORD` — ваша учётка суперадмина.

**Установщик.** GitHub → **Actions** → **Windows app** → последний зелёный запуск ветки `claude/stage6` →
**Artifacts** → `Sinf-setup-x64`.

**Кто есть кто:**

- **Ноутбук (Windows)** — сайт (`pnpm build`, затем `pnpm start`, порт 3000) и одновременно ПК учителя.
  Sinf учителя сам возьмёт свободный порт: 3000 занят сайтом.
- **ПК** — компьютер ученика.
- **Если ноутбук не на Windows:** ПК — учитель, а «ученик» — браузер телефона в той же сети (веб-режим,
  код урока). Блоки про киоск (6) и установку ученика переносятся.

**Журнал установки.** Установщик запускайте с `/LOG="C:\sinf-setup.log"`: при ошибке это первое, что я
попрошу.

**Анкета.** Заполните `docs/hardware-survey.md` по ПК (5 минут).

## День 1 — класс на ПК (около 3,5 часа)

| Блок | Что | Где написано | Время |
|---|---|---|---|
| 1 | Сайт на ноутбуке; школа, лицензия, учитель, класс «5А», код компьютера | `pc-test.md` 8.1–8.2 | 25 мин |
| 2 | Установка: ноутбук — учитель (привязка к сайту, вход своей учёткой); ПК — ученик `/ROLE=student /PC=ПК-01` | `pc-test.md` 8.3–8.4, `hardware-test.md` 4з | 25 мин |
| 3 | Урок на ПК: вход по рассадке, «Внимание!», миниатюры, показ экрана, программы и рабочая папка, Paint, Word с автопроверкой, «Мои работы», оценки на сайте | `hardware-test.md` 3, 4, 4а–4ж; `pc-test.md` 8.5 | 75 мин |
| 4 | Замеры по ходу блока 3 | `perf-baseline.md` | — |
| 5 | Урок офлайн | `pc-test.md` 8.6 | 25 мин |
| 6 | Киоск и побег | `escape-checklist.md`, `hardware-test.md` 5 | 30 мин |
| 7 | Прочее на ПК | `pc-test.md` 8.7, 5 | 20 мин |

Подробности к блокам:

- **Блок 2.** Замер: холодный старт ПК ученика — от входа в Windows до экрана «Учитель ещё не начал урок».
- **Блок 3.** В `hardware-test.md` вместо класса 1А берите «5А» с сайта; урок — любой из библиотеки или
  свой. Демо-класс 1А тоже есть на ПК учителя, если нужен урок 10 «Предыдущий — последующий».
- **Блок 4.** Записать:
  - ОЗУ и процессор ученика в простое;
  - процессор ученика, пока у учителя открыта панель класса (миниатюры);
  - ОЗУ учителя с уроком.
- **Блок 5.** Остановите `pnpm start` (Ctrl+C): Sinf учителя продолжает работать. Вход учителя без сайта,
  урок, «1 урок ждёт связи», снова `pnpm start` — всё доехало.
- **Блок 6.** Строки чек-листа с пометкой «агент» пропустите. Ещё: выход по паролю, `--dev` и `--setup`
  просят пароль, после перезагрузки Sinf открылся сам.
- **Блок 7.** Отзыв лицензии; английский; Scratch, Arduino, Python — если стоят на ПК; удаление Sinf.

## День 2 — веб в браузере (около 3,5 часа, можно частями)

В порядке важности:

1. Журнал, КТП, eMaktab, импорт оценок — `web-test.md` 8–12.
2. Свой урок, слайды из PDF, тест, практика, программа, библиотека — `web-test.md` 1–7.
3. Школа: правила, квоты, срок хранения, панель администратора, приглашения, сброс пароля, карточки с

5. Выгрузку журнала откройте в **настоящем Excel**: узбекская отметка отсутствия «yo‘q», пороги
   оценки 90/70/50.

## Как сообщать в VSCode

- **Одно сообщение — одна проблема** (или пачка мелких):
  - «блок N / пункт» или «`web-test.md` 8, шаг 3»;
  - что сделали, что ожидали, что получилось;
  - важность: **блокер** (дальше не пройти), **мешает** (обходится, но плохо), **мелочь**;
  - снимок экрана — прямо в чат.
- **Журналы** — путь или содержимое:
  - сервер учителя: `%LOCALAPPDATA%\Sinf\logs\server.log`;
  - установщик: `C:\sinf-setup.log`;
  - обновление: `C:\Program Files\Sinf\updates\updater.log`;
  - сайт — окно, где запущен `pnpm start`.
- Таблицу `docs/test-results.md` заполнять не обязательно: я веду её по вашим сообщениям.
- **Исправления:**
  - сначала блокеры;
  - каждое — отдельный коммит в `claude/stage6` и зелёный CI;
  - вы перепроверяете только этот пункт;
  - если исправление требует нового решения, сначала спрошу (CLAUDE.md §9.2).
